# SGLang `/metrics` contract at a pinned upstream revision

Research date: 2026-09-25. Scope: SGLang **SRT language-model HTTP server**, with the legacy SMG gRPC sidecar called out separately. Source pin: [`sgl-project/sglang@2f5c9ac43d76eef11e8561c89c55a79db7db715a`](https://github.com/sgl-project/sglang/tree/2f5c9ac43d76eef11e8561c89c55a79db7db715a) (the `main` HEAD resolved by `git ls-remote` during this research). This is source inspection only: no server, model, GPU, endpoint, or host was exercised. It is not evidence that the TabbyAPI deployment in this repository implements these metrics.

## Route, enablement, and exposure

- `--enable-metrics` defaults to **false**; the default SRT HTTP bind is `127.0.0.1:30000`. The [production metrics guide](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/docs_new/docs/references/production_metrics.mdx) describes the flag and example scrape. The source of truth for defaults is [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/arg_groups/fields/observability.py#L70) and [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/arg_groups/fields/serving.py#L65). Inspect the actual launch command and bind before planning a scrape.
- With metrics enabled, startup sets `PROMETHEUS_MULTIPROC_DIR` **before** importing the client in worker processes, then mounts `prometheus_client.make_asgi_app` at `/metrics` with `CollectorRegistry` and `MultiProcessCollector`. A regex avoids a `/metrics` redirect. The scrape is Prometheus text exposition, not a versioned JSON snapshot. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/engine.py#L1835); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/common.py#L2660); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/common.py#L2676); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/http_server.py#L294).
- `/metrics` is explicitly allowed without credentials by the API-key middleware, even when `--api-key` or `--admin-api-key` is configured. It shares the server's bind; network access controls must protect it if needed. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/auth.py#L89). HTTP request/response/active counters are added when enabled, and can expose the route/method/status. Unknown unhandled paths become raw `endpoint` label values, a cardinality risk. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/http_server.py#L2621); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/common.py#L2711); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/common.py#L2750).
- Legacy `--smg-grpc-mode` instead starts an unauthenticated aiohttp sidecar on `--smg-http-sidecar-port` or `--port + 1`, on the configured host, and registers GET `/metrics` using `prometheus_client.openmetrics.exposition.generate_latest`. A missing/failed sidecar can leave gRPC serving without metrics; a too-old `smg-grpc-servicer` with metrics requested raises. This does **not** describe the ordinary HTTP route. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/grpc_server.py#L41); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/grpc_server.py#L175); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/arg_groups/fields/observability.py#L72).

## Reading the values

`Gauge` values are current/last published state; `Counter` values are cumulative in a process lifetime and require `rate()`/`increase()` for window rates; `Histogram` yields `_bucket`, `_sum`, and `_count` series. `GaugeHistogram` is SGLang's current distribution snapshot, not an event histogram. Do not infer a zero from an absent series. The collector definitions and update methods are [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L255); the custom gauge histogram uses **noncumulative** `gt`/`le` labeled gauge buckets and is [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/gauge_histogram.py#L1).

Scheduler base labels are `model_name`, `engine_type`, `tp_rank`, `pp_rank`, `moe_ep_rank`, optional `dp_rank`, and configured extra labels. Tokenizer base labels are `model_name`, `engine_type`, optional priority/custom/extra labels; `is_streaming` is added to some request counters and latency histograms. Some series add `mode`, `category`, `stage`, `cache_source`, `phase`, `source`, or other category labels. Scheduler recording defaults to the statistics rank; `--enable-metrics-for-all-schedulers` changes that and can multiply series. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1122); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/managers/tokenizer_manager.py#L785); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/arg_groups/fields/observability.py#L82).

The normal tokenizer update path records `prompt_tokens_total`, `generation_tokens_total`, `num_requests_total`, and length/E2E histograms **when a request finishes**. TTFT is observed at its first output (outside prefill-only disaggregation); inter-token latency divides an output interval by the number of new tokens and observes that value once per new token. These are engine-observed timings, not proof of client-perceived wire timing. Abort has a separate counter; HTTP errors have status-labeled response counters, but there is no single all-causes inference-failure counter. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/managers/tokenizer_manager.py#L3037); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1780); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1837).

`sglang:gen_throughput` is a scheduler gauge in tokens/s, while `sglang:realtime_tokens_total{mode="prefill_compute|prefill_cache|decode"}` is a counter; the current decode producer increments it on each decode iteration, although its declaration documentation says "updated on each log interval." `sglang:prefill_effective_tokens_total{mode="input|device_hit|host_hit|storage_hit"}` excludes retracted-request recounts and is the better numerator/denominator for windowed prefix-cache hit estimates. `sglang:cache_hit_rate` is a recent scheduler gauge, not a lifetime ratio. `sglang:token_usage` is the **maximum** utilization fraction across full/SWA/Mamba pools, not a token count; use absolute KV gauges for counts. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L69); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L900). Many scheduler gauges can lag a scrape because heavier decode reporting is periodic (`--decode-log-interval`, default 40 decode iterations); event counters and histograms follow their respective producers. The decode realtime counter is incremented per iteration. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/arg_groups/fields/observability.py#L136); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/managers/scheduler_components/metrics_reporter.py#L889).

The `PROMETHEUS_MULTIPROC_DIR` is a temporary directory created for the run (nested under a user-specified parent when supplied). Counters reset when the server/process restarts; gauges represent the latest publishing process with `mostrecent` in many declarations. A scraper may mark disappeared time series stale, but the endpoint itself does not provide a fresh-sample timestamp for every gauge. Do not compare raw counter values across restarts or interpret retained/absent series as current state without scrape health and age. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/utils/common.py#L2658); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L281).

## Exact declared SRT metric names

This inventory is generated from `Gauge`, `Counter`, `Histogram`, and `GaugeHistogram` declarations in the pinned `metrics_collector.py`; links point to each declaration. They are **possible** families, not a promise that every line appears on an idle server: feature flags, model architecture, disaggregation mode, rank, lazy label creation, and execution path matter. For histograms, the listed family expands to `_bucket`/`_sum`/`_count`; `GaugeHistogram` uses its own snapshot bucket representation. Units follow the metric suffix or declaration documentation. For names without a unit suffix, use the declaration and producer; some are counts, while others are ratios, throughput, or occupancy.

The section heading identifies each family's implementation collector; the link on each row gives its exact declaration. This table summarizes when those collectors receive values:

| Collector | Producer and update behavior |
| --- | --- |
| Scheduler (98 families) | Scheduler metrics reporter publishes queue, batch, token/cache, throughput, and speculative state. Some gauges update at a configurable decode-log interval; counters and phase histograms follow their own events. | Tokenizer (16) | Tokenizer manager records request totals, token lengths, and E2E on completion; TTFT on first output; ITL on later output intervals. ## Conditional semantics and limits

- Queue and scheduler series are **server internal**. `num_queue_reqs` is waiting requests; grammar and PD queue families split other stages. `queue_time_seconds` and `per_stage_req_latency_seconds{stage=...}` are scheduler-side histograms. They do not include arbitrary upstream gateway queueing. The `stage` values are defined by [request timing stages](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/req_time_stats.py#L1), and are conditional on stage observation.
- Speculative families (`spec_accept_length`, `spec_accept_rate`, `spec_cap_length`, `spec_block_accept_length`, active `spec_num_steps`, active `spec_num_draft_tokens`, and tokenizer `spec_verify_calls_total`) describe the active algorithm and completed requests, not an independent quality score. The declaration comments explicitly distinguish proposed drafts, accepted drafts, bonus token, and DSpark-specific caps. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L425); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1562).
- `is_streaming` splits some finished-request counters and TTFT/E2E histograms, **not** all metrics. Streaming-session occupancy families exist only with streaming sessions enabled. There is no per-chunk network flush latency or SSE delivery throughput family in this collector. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L670); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1739).
- `cached_tokens_total{cache_source=...}` uses device/host/storage when breakdown exists, and may use `total` fallback. Storage/radix/encoder cache metrics are separate and feature dependent. Prefix hits cannot be equated with end-user latency reduction without a workload measurement. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1632); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1800).
- `priority` can be a request-provided integer label, with an empty-string total series, and previously seen priorities remain as zero-valued series. Allowed request custom-label **names** are configured, but their **values** come from an HTTP header; do not permit user IDs, prompts, tenant secrets, or arbitrary high-cardinality values there. `model_name`/extra labels and raw unknown HTTP route paths can also reveal deployment details. Metrics contain aggregate sizes/timings, not raw prompts or completions by their declared contract. [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L48); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/observability/metrics_collector.py#L1185); [source](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/python/sglang/srt/entrypoints/openai/serving_base.py#L228).
- `num_requests_total` counts finished inference requests and `num_aborted_requests_total` counts aborts; HTTP response counters cover status classes but do not resolve all model/server failures into a normalized error reason. Empty/missing series may mean untriggered path, disabled feature, disabled metrics, wrong endpoint, or scrape failure. Source alone cannot establish the exact exposed set or values for a specific live installation.

## Reproducible read-only checks for a future authorized deployment

1. Record the installed SGLang package/revision, effective launch arguments, bind address, mode (HTTP or legacy gRPC), and any ingress/proxy path. Check `--enable-metrics`, `--enable-metrics-for-all-schedulers`, custom labels, and disaggregation options without changing them. Do not assume this source pin matches an installed version.
2. If an endpoint read is separately authorized, GET the **metrics route only**; this does not generate inference. Record HTTP status, content type, scrape timestamp, and a retained raw exposition snapshot. The plain `curl -fsS http://<allowed-host>:<port>/metrics` example is in [official docs](https://github.com/sgl-project/sglang/blob/2f5c9ac43d76eef11e8561c89c55a79db7db715a/docs_new/docs/references/production_metrics.mdx#L1). Restrict access because the route bypasses API keys.
3. Compare `# HELP`/`# TYPE` names and labels to the pinned inventory, keeping absent, zero, and stale distinct. Check two passive scrapes for counter monotonicity and gauge sample age; do not send a synthetic scored or inference request. Any workload-dependent field that never appeared remains **unverified**, not unsupported.

No endpoint call, installation, download, GPU test, or host mutation was performed for this report.
