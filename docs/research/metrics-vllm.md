# vLLM `/metrics`: pinned source audit

**Scope and evidence.** Read-only source audit on 2026-09-25 of upstream `vllm-project/vllm` commit [`25b0add7b8a1c944d5c4e364f2de6aa82497a2ad`](https://github.com/vllm-project/vllm/tree/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad) (then `HEAD`), primarily its V1 OpenAI-compatible serving path. This is a source contract, not an installed-host or live scrape result. The [production metrics guide](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/docs/usage/metrics.md#L1-L55) describes that path but expands metric tables at documentation-build time from source; definitions below therefore cite the code. Conditional connectors, diffusion, Ray, and HTTP middleware add other series, so the inventory is not a guarantee that every series appears in a given deployment.

## Endpoint, authentication, and wire format

The ordinary app registers the serve routers, which register the instrumentator, which calls `metrics.attach_router`: [app](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/launchers/app.py#L34-L54), [router chain](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/__init__.py#L19-L22), [instrumentator registration](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/instrumentator/__init__.py#L7-L18). The implementation adds Prometheus FastAPI HTTP instrumentation and a `make_asgi_app` mount at `/metrics`, with a regex adjustment to avoid the slash redirect. `/metrics`, `/health`, `/load`, `/ping`, `/version`, and `/server_info` are excluded from HTTP request instrumentation. There is no separate metrics-enable flag in this registration path. The response class declares `prometheus_client.CONTENT_TYPE_LATEST`, documented there as `text/plain; version=0.0.4; charset=utf-8`; expect Prometheus `# HELP`, `# TYPE`, and sample lines, not JSON. [Route and content-type source](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/instrumentator/metrics.py#L52-L81).

`--api-key` or `VLLM_API_KEY` installs the standard authentication middleware, but its guarded prefixes are `/v1`, `/v2`, `/inference`, `/cohere`; `/metrics` is outside them. Thus the built-in API key does **not** protect the metrics route at this pin. A custom middleware or external proxy may still restrict it. [Middleware registration](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/middleware/register.py#L19-L36), [path test](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/middleware/authenticate.py#L11-L22), [implementation](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/middleware/authenticate.py#L47-L62).

The server creates an auto-cleaned `PROMETHEUS_MULTIPROC_DIR` for multiple API server processes; if the operator provides that variable, vLLM warns the directory must be emptied between runs. The scrape uses a fresh `CollectorRegistry` plus `MultiProcessCollector` when that variable exists, otherwise the default registry. Logger creation unregisters pre-existing `vllm:` collectors; its gauges use `mostrecent` for scheduler/cache state and `sum` for the LoRA info gauge. Multiprocess setup is conditional on `api_server_count > 1`, while Prometheus logging is attached by `StatLoggerManager` even when default text logging is disabled. [CLI setup](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/cli/serve.py#L266-L280), [registry and cleanup](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/prometheus.py#L13-L80), [logger construction](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L454-L486), [default attachment](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1230-L1280).

## Update points and interpretation

`PrometheusStatLogger.record` sets running, waiting, waiting-by-reason, and KV usage from `SchedulerStats`; waiting includes ordinary plus skipped/deferred requests. It increments prefix-cache counters from scheduler query/hit deltas; external connector and speculative counters advance only when those stats exist. It then increments preemptions, prompt tokens, token-source counters, cached tokens, and generation tokens from `IterationStats`. Prompt sources separate actual local compute from local cache hits and external transfers. The iteration-token histogram observes locally computed prompt tokens plus generated tokens, not necessarily the full logical prompt length. [Record scheduler](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1027-L1115), [record iteration/finish](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1117-L1193), [prompt source invariants](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/stats.py#L387-L425).

TTFT is sampled on the first prefill output using frontend arrival time (currently when tokenization starts) to frontend iteration timestamp. ITL is sampled for each later engine output event using successive engine-core timestamps; one event can contain multiple tokens. At finish, queue time is first scheduled minus queued, prefill time is first new token minus first schedule, decode time is last minus first new token, inference time is last new token minus first schedule, and e2e is finish iteration timestamp minus frontend arrival. Preemptions can extend prefill/decode intervals. TPOT is `decode_time / (generation_tokens - 1)`, or **zero** for at most one generation token. The finished-request histograms and `request_success_total` therefore lag active work, and aggregate distributions cannot reconstruct individual request traces. [Output timing](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/stats.py#L428-L505), [finish calculations](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/stats.py#L532-L581), [upstream ITL/TPOT explanation](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/docs/design/metrics.md#L68-L80).

## HTTP and Python-client series

The vLLM code invokes the instrumentator with `.add().instrument(app).expose(app)`; version **8.0.0** of that official dependency installs its default five families when no custom instrumentation function is supplied. vLLM only requires `prometheus-fastapi-instrumentator >= 8.0.0`, so a later installed version can change this inventory. The middleware excludes `/metrics` and selected health/control routes. Its default groups status codes (for example `2xx`) and includes streaming response duration unless configured otherwise. These are HTTP request measurements, not engine output/finish measurements. There is no general `vllm:*errors_total` family in the standard core constructor. `vllm:request_success_total{finished_reason="error"}` represents the request-level `ERROR` enum only if that finish event reaches the logger; the enum's `__str__` maps numeric values to text labels. HTTP status-class counts cover API errors and rejections separately; logs remain necessary for causes. Exact status/finish label values should be verified on the actual deployment before encoding alert rules. [Core finish counter](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L728-L740), [finish enum and string mapping](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/engine/__init__.py#L36-L69).
## Operational limits and reproducible checks

- **Cardinality/privacy:** core labels are bounded by served models, engine count, fixed reasons/sources, and configured draft positions. LoRA adapter **names** are joined into `waiting_lora_adapters`/`running_lora_adapters` labels and can create changing, potentially sensitive series; the code itself warns LoRA metrics may be misleading in data-parallel deployments. `cache_config_info` exposes configuration in labels. HTTP handler labels expose route names, not prompt text. Review access to the unauthenticated route. [LoRA source](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L975-L1025), [LoRA update](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1099-L1111).
- **Resets/staleness:** counter process restarts reset series; Prometheus `rate()` handles resets if scrapes preserve continuity. Gauges update on stats receipt, so an idle, wedged, or disconnected frontend can leave the last value visible until scrape failure/staleness handling. User-owned multiprocess directories retained across runs can expose inaccurate old values. A zero sample differs from an absent family; conditional metrics can be absent. [Registry lifecycle](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/prometheus.py#L17-L80), [record path](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1027-L1050).
- **Known source caveats:** code marks `iteration_tokens_total` and `lora_requests_info` potentially incorrect under multiple API servers; it warns LoRA can mislead under data parallelism. This is a metrics source audit, not a validation of scrape consistency under those configurations. [Iteration caveat](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L775-L786), [LoRA caveat](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L979-L987).
- **Deprecation:** upstream documents: deprecated in `X.Y`, hidden in `X.Y+1` with `--show-hidden-metrics-for-version=X.Y` escape hatch, removed in `X.Y+2`. The inspected core constructor has a `show_hidden_metrics` config field but no specific deprecated core family gated by it at this pin. The offloading connector separately registers three explicitly deprecated compatibility families shown above; those update only on its CPU offload path. [Policy](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/docs/usage/metrics.md#L52-L56), [core field](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L471-L478), [offload compatibility](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/distributed/kv_transfer/kv_connector/v1/offloading/metrics.py#L132-L151).
- **Streaming:** `/metrics` is a scrape snapshot, not a stream or per-request event feed. TTFT/ITL can advance during streamed generation, whereas finish-only histograms do not. The route itself makes a regular ASGI Prometheus response. [Route](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/entrypoints/serve/instrumentator/metrics.py#L52-L81), [record loops](https://github.com/vllm-project/vllm/blob/25b0add7b8a1c944d5c4e364f2de6aa82497a2ad/vllm/v1/metrics/loggers.py#L1142-L1193).

Read-only reproduction, requiring no model inference or installation:

```sh
git clone --depth 1 --filter=blob:none --sparse https://github.com/vllm-project/vllm.git /tmp/vllm-metrics-audit
git -C /tmp/vllm-metrics-audit fetch --depth 1 origin 25b0add7b8a1c944d5c4e364f2de6aa82497a2ad
git -C /tmp/vllm-metrics-audit checkout --detach 25b0add7b8a1c944d5c4e364f2de6aa82497a2ad
git -C /tmp/vllm-metrics-audit sparse-checkout set vllm/v1/metrics vllm/v1/spec_decode vllm/entrypoints/serve vllm/entrypoints/launchers vllm/entrypoints/cli
rg -n 'name="vllm:|Mount\("/metrics"|GUARDED_PREFIX|setup_multiprocess_prometheus' /tmp/vllm-metrics-audit/vllm
```

On an **already authorized, running** vLLM server, `curl -i http://HOST:PORT/metrics` is a read-only scrape and verifies actual content type and present families; `curl -sS http://HOST:PORT/metrics | rg '^# (HELP|TYPE) vllm:'` lists exposed families. No such scrape was made for this report. The exact active metric inventory, multiprocess consistency, HTTP exporter version, and host-specific authentication/proxy behavior remain live unknowns.
