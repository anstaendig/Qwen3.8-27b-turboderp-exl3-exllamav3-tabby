This is a **source audit**, not an installed or live endpoint check. Recheck the source if deploying a different build. The [upstream endpoint table](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/README.md#L1122-L1150) is useful but omits `prompt_tokens_cached_total`, which is emitted by the pinned implementation.

## Route, access, and shape

`GET /metrics` is registered in both single-model and router modes; there is no `/v1/metrics` registration here. Router mode replaces the handler with a proxy and requires `?model={model_id}`. The flag `--metrics` (or `LLAMA_ARG_ENDPOINT_METRICS`) enables the endpoint; the default is disabled. When disabled, the handler returns the server's unsupported-endpoint error, rather than an empty Prometheus document. Sources: [route and router dispatch](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server.cpp#L207-L255), [flag](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/common/arg.cpp#L3586-L3593), [handler](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L4657-L4726), [router requirement](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/README.md#L1122-L1127).

The default listener is `127.0.0.1:8080`; `--host` can expose it elsewhere. With configured `--api-key` or `--api-key-file`, `/metrics` requires the same key as other nonpublic routes (Bearer authorization or `X-Api-Key`); only health and UI paths bypass the key check. With no API keys, it is unauthenticated. The response is `text/plain; version=0.0.4` with `# HELP`, `# TYPE`, and `llamacpp:` samples. Scrapes return a `Process-Start-Time-Unix` header, **but its value is not Unix time**: the server assigns `ggml_time_us()`, which uses a monotonic clock on POSIX (and a performance counter relative to `timer_start` on Windows), in microseconds. Treat it as an opaque process-identity aid rather than a Unix timestamp. Sources: [listener and key defaults](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/README.md#L192-L213), [authentication middleware](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-http.cpp#L250-L303), [response](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L4664-L4725), [start assignment](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-common.h#L480-L486), [clock implementation](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/ggml/src/ggml.c#L547-L573).

All samples are unlabeled **except** speculative acceptance by draft `position="N"`. In router mode, `model` is a routing query parameter, not a sample label; scrape targets must keep model identities distinct. No prompt text, completion text, request ID, user ID, path, or API key is placed in `/metrics` samples. Exposing the endpoint still reveals workload volume, activity, throughput, cache reuse, and speculative performance. Position label cardinality is bounded by configured draft length, not request count. Sources: [exposition formatter](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-task.cpp#L1593-L1618), [position vector allocation](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L3978-L3989).

## Exact emitted series at this commit

The [formatter is authoritative](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-task.cpp#L1517-L1618); the [metric accumulator](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-common.h#L440-L503) defines the rates and reset behavior. Units below are the actual values emitted, irrespective of naming conventions.

| Series (prefix `llamacpp:`) | Type | Value and unit | Implementation/update |
| --- | --- | --- | --- |
| `prompt_tokens_total` | counter | Processed prompt tokens, excluding cache hits. | Added after target batch decode and synchronization. |
| `prompt_tokens_cached_total` | counter | Prompt tokens reused from slot cache. | Added when a slot establishes its cached prefix. |
| `prompt_seconds_total` | counter | Accumulated prompt processing time, seconds (internal microseconds / 1e6). | Timed target prompt batch, flushed after synchronization. |
| `tokens_predicted_total` | counter | Generated tokens credited when a slot is reset. | Transferred from slot accumulator on reset. |
| `tokens_predicted_seconds_total` | counter | Accumulated generation time, seconds, credited with those tokens. | Transferred from slot accumulator on reset. |
| `n_decode_total` | counter | Target `llama_decode()` calls counted in the server decode path; excludes speculative and multimodal decoding per HELP text. | Incremented after target decode. |
| `n_tokens_max` | **counter in exposition** | High watermark of observed sequence length (prompt plus generation), tokens. Semantically a nondecreasing maximum, not an additive event counter. | Maximum updated as slot work advances. |
| `spec_decode_num_draft_tokens_total` | counter | Draft tokens generated. | Transferred from slot accumulator on reset. |
| `spec_decode_num_accepted_tokens_total` | counter | Draft tokens accepted by target. | Transferred from slot accumulator on reset. |
| `spec_decode_num_drafts_total` | counter | Speculative verification steps. | Transferred from slot accumulator on reset. |
| `prompt_tokens_seconds` | gauge | Average *processed* prompt tokens/second in the bucket since the preceding scrape. | Computed and bucket reset by each scrape. |
| `predicted_tokens_seconds` | gauge | Average generation **decode steps**/second in that bucket; the first generated token is excluded from steps although it is included in `tokens_predicted_total`. | Computed and bucket reset by each scrape. |
| `requests_processing` | gauge | Number of slots whose state is not idle at snapshot time; includes prefill and generation. | Counted from slot state at scrape. |
| `requests_deferred` | gauge | Size of the deferred task queue waiting for a slot; does not claim to count every HTTP request or every item in the main task queue. | Read from deferred queue at scrape. |
| `n_busy_slots_per_decode` | gauge | Cumulative busy-slot observations divided by cumulative target decode calls (denominator at least 1); it is an average over process life, not a scrape-window rate. | Accumulates after target decode; ratio at scrape. |
| `spec_decode_num_accepted_tokens_per_pos_total{position="N"}` | counter | Accepted draft tokens at zero-based draft position. The labeled family is absent until the position vector is populated by speculative work. | Position accumulators transferred on slot reset. |

The first ten rows are emitted as counters, the next five as gauges, and the final labeled family as a counter. Sources: [series and types](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-task.cpp#L1522-L1618), [decode-step and bucket formulas](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-common.h#L403-L409), [slot state](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L462-L469), [deferred queue size](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-queue.h#L107-L111).

## Collection and interpretation

The server context owns the cumulative `server_metrics`; `/metrics` posts a high-priority task to that context, which snapshots the accumulator plus current slot and deferred-queue counts. It is not a per-request instrument. Cache reuse is counted when a slot establishes its cached prompt prefix. Uncached prompt tokens and compute time are queued around target batch decode and flushed only after synchronization (or once idle), so a scrape during an asynchronous prefill may temporarily lag. Decode calls and busy-slot observations are recorded after target decode. Generation tokens/time and speculative totals are transferred from a slot to server totals on slot reset; an in-flight stream's partial generation can therefore be absent from cumulative totals until reset. Sources: [context snapshot](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L2501-L2522), [cache reuse](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L3403-L3413), [batch accounting](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L4041-L4148), [slot reset callback](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L1302-L1311).

Each successful live scrape copies cumulative values and **then resets only the prompt/predict rate buckets**; the next scrape measures work since the previous one. A scrape during server sleep uses cached metrics and resets the cached buckets, then resets live buckets on wake. Consequently, concurrent or irregular scraping changes the meaning of both throughput gauges; a scrape with no new timed work yields 0, while cumulative counters persist until process/context reinitialization. `n_busy_slots_per_decode` remains cumulative. The misnamed `Process-Start-Time-Unix` header can help identify a process change, but it is not a Unix timestamp. Sources: [live and sleeping scrape paths](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L4664-L4726), [sleep/wake cache](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-context.cpp#L5544-L5558), [bucket reset](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-common.h#L484-L502).

The endpoint has **no direct phase split** for active prefilling versus active decoding, no TTFT or per-request/end-to-end latency series, no completed/failed request counter, no streaming-chunk or time-between-token series, and no cache occupancy, KV memory, GPU memory, or eviction series. Prompt and generation *aggregate compute* time, token totals, and current busy slots support coarse service monitoring; they cannot reconstruct a specific request's TTFT, latency distribution, or exact current phase. `prompt_tokens_cached_total` is a reuse count, not a cache hit ratio without a defined denominator and request boundary. `requests_deferred` is only the server's deferred queue, so zero does not prove absence of all waiting work. These gaps follow from the complete [emitted series list](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-task.cpp#L1517-L1618) and [queue structure](https://github.com/ggml-org/llama.cpp/blob/e85e15cf6d810cd1268498c2e5b657bb3ece47bc/tools/server/server-queue.h#L22-L29).

## Reproducible read-only checks

For a **locally built server that is already running with `--metrics`**, inspect without inference, installs, or model downloads:

```sh
# Use the actual listening address, and add -H 'Authorization: Bearer …' when configured.
curl -fsS -D - http://127.0.0.1:8080/metrics
# Router mode: URL-encode the intended model ID in ?model=… .
```

Check HTTP 200 and `Content-Type: text/plain; version=0.0.4`, parse `# TYPE` and values, and compare the observed metric-name set against the table above. Use a **single** scraper for interval throughput gauges; repeated manual GETs also reset their buckets. Source-only verification is reproducible by fetching the pinned files above and comparing `server_task_result_metrics::to_metrics`, `server_metrics`, and `server_routes::get_metrics`. Do not infer live availability from this report or from a successful source check. This is a candidate server's endpoint, not the TabbyAPI endpoint used by this repository's current native deployment.
